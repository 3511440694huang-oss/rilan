# 日览 · Rilan

**本地优先的 Android 日报。** 每日壁纸、按定位取的天气、中文信息流与热榜、日程提醒、周期回望，
都放在一屏能左右翻完的四张玻璃卡里；另开一个只监听回环的 MCP 服务，让外部 AI 读写这份日报。

> 目标系统：Android 8.0 – Android 15（API 26–34）；`compileSdk 36` / `targetSdk 34` / `minSdk 26`。

![日览图标](icon-preview.png)

## 功能

- **每日壁纸**：必应每日图，按设备当天命名复用，一天只下一次；解码时按屏幕短边采样，
  整张 4K 图不进内存。两张图之间 0.6 秒交叉淡入，没有网络时回退到自带的渐变底。
- **天气**：默认自动定位，只用于天气。实况每 60 秒、全量预报每 10 分钟、空气质量每 30 分钟。
  冷启动先显示上次的天气；没有缓存时先并行拉一次实况让温度上屏，再补全预报。
  三个数据源从串行兜底改成对冲竞速（主源 0.8 秒没动静就并行备源，谁先回用谁），整条链 9 秒硬截止；
  启动先预热 DNS，壁纸与信息流给天气让路。区县与街道走中文反向地理编码，同位置 24 小时内走本地缓存。
- **信息流**：RSS 与 JSON 两类来源插件，另内置微博、B站、抖音热榜。
  条目不再截断（综合 40 条 / 热榜 30 条 / 安全、世界 20 条），一直滑到底为止。
- **日程**：月历翻月、当天日程、生日提醒；到点走系统闹钟通道提醒，与每日通知互不影响。
  日程页新增「纪念日」分段：生日、纪念日、倒计时都在这里数天——纪念日显示「已经 N 天」，
  生日 / 倒计时显示「还有 N 天」，每年重复的标出「第 N 个」；首页「今天」卡也带上最近三条。
- **回望**：收录条目按周期统计，可让外部 AI 或 DeepSeek 直连写回一段周期总结。
- **今日简报**：用 DeepSeek 把当天的天气、信息流和日程读成一段总览，可选功能，Key 只存本机。
- **每日通知**：默认 08:00，内容带 36 小时内的天气缓存与今天未完成的日程，点通知直接进首页。
- **导出**：收录条目可导出 Markdown / CSV，Android 10 以上写入「下载/日览/」，旧系统改为系统分享。
- **本机 MCP**：只绑 `127.0.0.1`，Bearer token 鉴权，19 个工具 + 5 个 `rilan://` 资源，
  外部 AI 能读天气、信息流、日程和收录条目，也能新建日程、加来源、写回简报与周期总结。
- **本地优先**：没有账号，没有统计 SDK，没有广告；数据只在本机的应用私有目录里。

## 安装

1. 下载 `rilan-1.8.0.apk`，允许「安装未知来源应用」后安装。
2. 首次启动会说明定位用途并请求权限；拒绝也不影响信息流、日程与回望，只是天气改用城市名手动指定。
3. Android 13 及以上，打开「今日简报」通知开关时会请求通知权限；没有权限时通知静默跳过，不会崩溃。
4. 想让每日通知或 MCP 在开机后自动恢复，可打开「扩展 → 更多 → 开机自启动」；
   部分系统（MIUI / ColorOS 等）还需要在系统设置里允许自启动与后台运行。

签名与 1.6.0 及更早版本一致，可直接覆盖安装并保留数据。

## 用法

首页是四张全屏玻璃卡，左右滑或点顶部页码切换：

| 卡片 | 内容 |
|---|---|
| 天气 | 实况、逐时、未来几天、空气质量，定位与刷新状态 |
| 简报 | 今日简报（DeepSeek 生成）与天气补充，可点「用 DeepSeek 总结今天」 |
| 信息 | 分类信息流与热榜，可一直向下滑 |
| 今天 | 今天要记得的事：日程、生日、收录进度 |

底部四页分别是「日报」「日程」「回望」「扩展」：日程页放整月月历与当天列表，回望页放周期统计与总结，
扩展页放来源管理、DeepSeek 配置、MCP 服务、每日通知与崩溃日志。

## 刷新节奏

| 内容 | 周期 | 说明 |
|---|---|---|
| 天气实况 | 60 s | Open-Meteo 的 `current` 本身是 15 分钟粒度，60 秒已是 15 倍过采样 |
| 全量预报 | 10 min | 逐时、逐日、空气质量一并刷新 |
| 信息流 / 热榜 | 3 min | 切到「信息」卡时再立即刷一次 |
| 定位 | 10 min | 后台补定位，不阻塞天气卡 |
| 前台心跳 | 20 s | 回到前台立即刷新；手动刷不再强制重新定位，信息流与壁纸等天气起跑后再发 |

信息流带 `If-None-Match` / `If-Modified-Since` 条件请求，服务器回 304 时直接复用上次正文
（实测 10 个中文源里 5 个支持）；HTTP 连接复用，去掉了 `Connection: close` 与成功后主动断开。

## 位置与天气

- 定位成功后按经纬度请求 Open-Meteo；区县与街道用 BigDataCloud 中文反向地理编码，
  同一位置 24 小时内走本地缓存，缺失时回退系统 Geocoder。
- 启动时先用上次坐标并行请求天气，定位和反查在后台补，拿到新坐标才再拉一次。
- 三个源不再串行等失败：主源立刻发，800ms / 1800ms 后并行备源，首个成功即取消其余；
  单次请求连接 2.5s / 读 6s，不叠加失败重试，整条链 9 秒硬截止。
- 启动时后台预解析天气域名，冷启动不再把 DNS 与双栈探测算进关键路径。
- 壁纸（几百 KB～数 MB）与十几个 RSS 源给天气让路：信息流延后 1.2 秒、壁纸延后 3 秒起跑。
- 没有缓存时先并行打一发轻量 `current`，温度先上屏，再补逐时与 7 天预报；这份占位数据只进内存、不落盘。
- 网络超时或服务暂时不可用时保留上一次成功的天气，卡片显示错误文案与「重试」，不会清空。
- Open-Meteo 免费层限额 10000 次/天、5000 次/时、600 次/分，按变量加权计费，当前节奏远低于限额。

## DeepSeek 与周期总结

1. 打开「扩展 → AI」，填入 DeepSeek API Key，选模型（`deepseek-flash` 更快更省，`deepseek-v4-pro` 更细）。
2. 点「测试连接」确认 Key 与网络正常，再保存。
3. 首页「简报」卡可生成今日总览；回望页可生成周期总结。

- 请求 `POST https://api.deepseek.com/chat/completions`，非思考模式，返回 Markdown 正文。
- Key 只存应用私有 SharedPreferences，不写日志、不上传；卸载即删除。
- 周期总结有两条路径：外部 AI 通过 MCP 读 `get_records` 再 `save_period_summary` 写回，
  或在回望页用 DeepSeek 直连生成。两种路径写回的数据结构一致，卡片会标注来源与生成时间。
- 日览没有内置 AI 对话，AI 相关能力都走 DeepSeek 或 MCP。

## MCP

### 启动

1. 打开日览 → 底部「扩展」→「服务」，点「启动 MCP」；点「检测连接」也会顺带启动并走一遍回环验证。
2. 看到「本机连接正常 · 19 个工具」后，点「复制 DSH 配置」，粘贴到 DeepSeek Harness 的 MCP 列表并重载。
3. 服务只绑 `127.0.0.1`，端口默认 `8765`，token 由 App 自动生成；扩展页另提供通用 JSON 给其他客户端。

```yaml
- id: mcp-rilan
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: rilan
    transport: streamable-http
    url: http://127.0.0.1:8765/mcp
    headers:
      Authorization: 'Bearer <扩展页复制的 token>'
```

### 工具

只读：`get_weather`、`get_news`、`get_briefing`、`search_news`、`get_records`、
`list_schedules`、`list_sources`，另有 5 个 `rilan://` 资源。

写入：

- 日程：`create_schedule`、`update_schedule`、`delete_schedule`
- 来源：`add_source`、`remove_source`、`set_source_enabled`
- 设置与刷新：`set_city`、`set_reminder_time`、`refresh_content`
- 写回内容：`save_weather_insight`、`save_daily_brief`、`save_period_summary`

写入后界面立即更新，重启后保留。

### 安全边界

- 只监听 `127.0.0.1`，不开放到局域网；服务停止即关闭端口，前台服务通知可直接停止。
- 所有请求都要 Bearer token，token 只存在本机应用私有存储。
- MCP 可以读写本机日程与来源，只连接你信任的 AI 客户端。

### 连不上时

- 先点扩展页「检测连接」：它验证端口、Bearer token、`initialize` 与 `tools/list`，失败会给出具体原因。
- 核对客户端里的地址与扩展页显示的 endpoint 完全一致，token 带不带 `Bearer ` 前缀。
- MCP 依赖前台服务存活；App 被系统冻结时回到前台会自动恢复。
- 提示端口被占用，通常是别的 App 占了 8765。

## 来源插件

插件目录：`Android/data/app.rilan.daily/files/plugins/sources/`，一个 `<id>.json` 一个来源，
文件名必须与 `id` 一致，删掉文件即删除来源。应用内「扩展 → 来源」可添加、编辑、从剪贴板导入、启停与删除。

首次启动写入默认中文来源与 `README.txt`；升级会移除旧版不可直连的英文默认源并补上中文源，
但不会恢复用户主动删除的旧源。

默认来源：IT之家、少数派、Solidot、爱范儿、中国新闻网、人民网、V2EX、掘金、机核、
橘鸦 AI 早报、量子位、知乎热榜、百度热搜、四叶草安全、Seebug Paper，以及中国新闻网 / 人民网的国际版；
微博、B站、抖音热榜由应用直接抓取，可在扩展页分别关闭。

### RSS

```json
{
  "schema": 1,
  "id": "my-rss",
  "name": "我的 RSS",
  "category": "GENERAL",
  "type": "rss",
  "url": "https://example.com/feed.xml",
  "enabled": true,
  "maxItems": 12,
  "headers": { "Referer": "https://example.com/" }
}
```

### JSON 接口

```json
{
  "schema": 1,
  "id": "my-json-hot",
  "name": "我的 JSON 热榜",
  "category": "WEIBO",
  "type": "json",
  "url": "https://api.example.com/hot/list",
  "enabled": true,
  "maxItems": 15,
  "mapping": {
    "items": "data.list",
    "title": "title",
    "url": "url",
    "source": "author.name",
    "time": "created_at",
    "hot": "hot_value",
    "snippet": "description",
    "linkPrefix": "https://example.com/item/"
  }
}
```

字段口径：

- `category`：`GENERAL` / `AI` / `ZHIHU` / `WEIBO` / `BILIBILI` / `DOUYIN` / `BAIDU` / `SECURITY` / `WORLD`
- `type`：`rss` 或 `json`；`maxItems`：1–40
- `mapping.items`：数组所在的点路径（`data.list`、`items.0.list`），留空表示响应根就是数组
- `mapping.url`：可以是完整 URL，也可以是 id 加 `linkPrefix` 拼成网页地址
- `time`：秒/毫秒时间戳，或 ISO / RFC1123 文本；`hot` 原样保留为热度字符串
- 热榜分类默认过滤明星娱乐，可在插件里设 `"filterEntertainment": false` 关闭

## 技术要点

- **玻璃卡**：整张卡的填充渐变、冷/暖光、反光、内阴影、颗粒与双层描边一次性画进一个独立图层，
  静态绘制按卡片尺寸缓存（`drawWithCache`），滚动时只做合成，不重算渐变。
- **动画只在绘制期读值**：天气大图标的旋转/飘移/下落、刷新转圈、加载小圆点、定位脉冲都只拿 `State`，
  在 `graphicsLayer {}` 或绘制块里读 `.value`，动画只更新那一个小图层，不触发重组。
- **手势不抢竖直滚动**：月历的「横向拖拽翻月」只在水平位移明显占优时接管（阈值 72 dp），
  竖直手势原样留给外层列表。
- **入场只播一次**：整屏入场动画每个进程只播一次，切 tab 回来不再逐帧半透明合成整屏。
- **滚动位置可恢复**：四张卡的 `ScrollState` 用 `rememberSaveable` 保存，翻页回收后回来不跳回顶部。
- **刷新链路**：前台心跳 + 条件请求 + 连接复用；失败保留上次数据，不清空界面。
- **稳定性**：信息流显示前按 id 去重、`Application.onCreate` 不做磁盘 IO、MCP 前台服务启动失败即自停，
  崩溃堆栈写在本机「扩展 → 更多 → 崩溃日志」。
- **MCP**：自己实现的 Streamable HTTP 端点，覆盖 `initialize`、`tools/list`、`tools/call`、通知与 DELETE 会话，
  带协议版本回退。

## 隐私

- 只有 `INTERNET`、定位、通知、开机自启、震动与前台服务权限；没有存储写权限，导出走 MediaStore 或系统分享。
- 无账号体系、无统计 SDK、无广告；壁纸、缓存、崩溃日志、Key 都在应用私有目录。
- 外部 AI 只能通过本机回环 MCP 访问数据，服务默认不对外监听。
